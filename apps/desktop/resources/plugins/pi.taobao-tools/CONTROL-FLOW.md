# 浏览器接管 / 交还 / 终止：完整闭环

适用于 PI-Desktop 内置浏览器，所有驱动方（内置 `Browser` 工具、取数插件、定时任务）一视同仁。

## 1. 状态

按 **sessionId** 独立维护，每个会话一个状态：

| 状态 | 含义 | 谁能进入 |
|---|---|---|
| `idle` | 没有 agent 在操作，用户可自由使用 | 初始值 |
| `agent` | agent 正在驱动页面（active > 0） | 仅 agent 的浏览器操作 |
| `user` | 用户接管，agent 一律被拒 | 仅用户点「接管」 |

不变式：

1. `user` 状态下，任何 agent 的浏览器操作返回 `HANDOFF_REQUIRED`，不会进入 `agent`。
2. `agent → idle` 只发生在该会话 turn 结束（或用户终止）时：turn 存续期间，操作之间的空隙仍保持 `agent`，控制条与页面走光不会随单次工具调用闪烁。
3. 用户动作永远优先：接管可以从任何状态进入 `user`。
4. 视图管线（`setBounds`/`setVisible`/`getState`/`reveal`）**不参与**状态机，避免状态抖动。
5. 每次状态变化都以 sessionId 广播；渲染层只处理自己会话的事件。

## 2. 用户动作与副作用

| 动作 | 状态 | 副作用 |
|---|---|---|
| 接管 `takeover` | → `user`（无论当前是什么） | ① 通过 `agent/abort` 中断当前 turn；② 该会话排队/在跑的 `run_automation` 在下一次浏览器操作处终止并记为 `cancelled`；③ 已提交给页面的脚本无法撤回，只能保证后续操作被拒 |
| 交还 `handBack` | `user` → `idle` | 不自动恢复 agent；用户下一条指令开始新 turn |
| 终止 `stop` | → `idle` | ① 优雅停止当前 turn（等同输入框 Stop）；② 取消排队/在跑的 `run_automation` |

「停止 turn」复用既有通道：`pi-desktop/agent/abort`（接管）与 `pi-desktop/agent/stop`（终止），与输入框停止按钮完全一致。

自动化运行还可以用 `cancel_automation_run { runId }` 单独取消：排队中的任务不会启动，
运行中的任务会在下一次浏览器操作前停止并记为 `cancelled`。已经提交给页面的点击/发布
无法撤回。

## 3. 人类介入场景矩阵

| 场景 | 期望行为 |
|---|---|
| agent 操作进行中，用户接管 | 该操作立即失败；turn 被 abort；状态 `user` |
| agent 空闲，用户接管 | 状态 `user`，控制条提示“已接管（当前没有进行中的任务）” |
| 用户接管后 agent 继续调工具 | 返回 `HANDOFF_REQUIRED`，消息明确说明“等待用户交还后用同一参数重试” |
| 用户交还 | 状态 `idle`；agent 不会自动重试，需用户再次指令 |
| agent 运行中，用户终止 | turn 被优雅停止；状态 `idle` |
| 用户接管中，用户终止 | 等价于交还 + 终止：状态 `idle` |
| agent 在用户接管期间自然结束 | 状态保持 `user`；浏览器仍归用户 |
| turn 自然结束（无用户动作） | turnEnd → `idle`，页面走光撤除 |
| 两次工具调用之间 | 保持 `agent`（静息态：慢转、走光呼吸） |
| 多个会话并行 | 状态按 sessionId 隔离，互不影响 |
| 同一会话多个标签页 | 共享同一控制状态（按会话，不按标签） |
| 定时任务驱动的操作 | 与普通 turn 相同；接管会中断它 |
| 排队中的 `run_automation` | 接管/终止时被取消，记录为 `cancelled(HANDOFF_REQUIRED)`，不阻塞后续任务 |
| 页面/标签关闭 | 丢弃该会话的 active 计数与租约 |
| 插件卸载 / 应用退出 | 状态全部丢弃（仅内存），无残留 |

## 4. 控制条与页面特效

控制条是**站点视图上方的一片原生透明浮层**（360×56，页面底部居中），不注入页面 DOM：

- 可见条件：`state != idle`，即整个 turn 期间常显，turn 结束即撤。
- `agent` 状态按钮：**接管 / 终止**；静息（无命令在飞）时底色变浅、指示环慢转。
- `user` 状态按钮：**交还 / 终止**；琥珀色。
- 文案：`agent` → “Agent 正在操作：<动作>” 或 “Agent 空闲（可接管）”；`user` → “你已接管浏览器”。

页面特效由宿主注入当前可见页（`browser-agent-glow.ts`），`pointer-events:none`：

- 四边 1px 轨道内白光段环绕（2.4s），四周暗角呼吸（3.8s）；
- 四边帘幕向中心收拢再收回（6.8s，四向错相）；
- 19px / 31px 两层错位的白色颗粒点阵（5.2s 呼吸），不是规则网格；
- 页面跳转后 3 秒内自动补挂；`idle` 时整层撤除；`user` 态改为静态浅框；
- 尊重 `prefers-reduced-motion`。

## 5. 错误契约

| 错误 | 触发 | agent 侧文案 |
|---|---|---|
| `HANDOFF_REQUIRED` | `user` 状态下发起浏览器操作 | “用户已接管浏览器，自动化暂停。请等待用户交还后用相同参数重试。” |
| `ABORTED` | 操作被 abort | 原样透传，agent 应停止本 turn |

## 6. 边界与已知限制

1. 已提交给渲染进程的 `executeJavaScript` 无法真正中断，只能保证其后续操作被拒绝。
2. 插件视图上报 bounds 时不带 sessionId，屏幕上的页面可能键为 `default`；控制状态在无匹配会话时会推给当前可见页面。
3. 接管会中断**整个 turn**，不只是浏览器操作——这是“立即中断”的语义代价。
4. 自动化 `run` 的状态机在插件进程内；控制状态变化时它靠“下一次浏览器操作被拒”自然终止，随后被标记为失败而非静默挂起。
5. 交还后不自动重跑：避免 agent 在用户没点头时继续操作页面。
